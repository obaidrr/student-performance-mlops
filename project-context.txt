================================================================================
PROJECT CONTEXT: Student Performance ML Pipeline
================================================================================

PROJECT OVERVIEW
----------------
This is an end-to-end MLOps pipeline that predicts student exam scores based on
19 input features. The system is built using Apache Airflow for orchestration,
scikit-learn for machine learning, FastAPI for the REST API, React for the
frontend, MySQL for data storage, and Docker Compose for containerization.

Dataset: StudentPerformanceFactors.csv
  - Source: dataset/raw/StudentPerformanceFactors.csv
  - Rows: 6,607 student records
  - Features: 19 (6 numeric, 13 categorical)
  - Target: Exam_Score (continuous, 0-100) — regression problem

================================================================================
DATASET DETAILS
================================================================================

Numeric Features:
  - Hours_Studied: Hours studied per day (0-24)
  - Attendance: Attendance percentage (0-100)
  - Sleep_Hours: Hours of sleep per day (0-24)
  - Previous_Scores: Previous exam scores (0-100)
  - Tutoring_Sessions: Number of tutoring sessions per week (0+)
  - Physical_Activity: Hours of physical activity per week (0+)

Ordinal Categorical Features (encoded with OrdinalEncoder):
  - Parental_Involvement: [Low, Medium, High]
  - Access_to_Resources: [Low, Medium, High]
  - Motivation_Level: [Low, Medium, High]
  - Family_Income: [Low, Medium, High]
  - Teacher_Quality: [Low, Medium, High]
  - Parental_Education_Level: [High School, College, Postgraduate]
  - Distance_from_Home: [Near, Moderate, Far]
  - Peer_Influence: [Negative, Neutral, Positive]

Binary Categorical Features (encoded with LabelEncoder):
  - Extracurricular_Activities: [Yes, No]
  - Internet_Access: [Yes, No]
  - Learning_Disabilities: [Yes, No]
  - Gender: [Male, Female]
  - School_Type: [Public, Private]

Target Variable:
  - Exam_Score: Continuous numeric value (0-100)
  - Problem Type: Regression

================================================================================
AIRFLOW DAGs (ML PIPELINE)
================================================================================

DAG 01: dataset_preprocessor_and_csv_to_mysql_dag.py
  DAG ID: 01_dataset_preprocessor_and_csv_to_mysql
  Purpose: Load, preprocess, and store data in MySQL
  Tasks:
    1. load_and_validate_dataset
       - Reads CSV from /opt/airflow/dataset/raw/StudentPerformanceFactors.csv
       - Validates schema and reports missing values
    2. preprocess_and_save_artifacts
       - Fills missing values (median for numeric, mode for categorical)
       - Applies OrdinalEncoder to ordinal categorical columns
       - Applies LabelEncoder to binary categorical columns
       - Applies StandardScaler to numeric features
       - Saves encoders and scaler as .joblib files to artifacts/preprocessing/
       - Saves metadata.json with feature names and column info
       - Saves preprocessed_data.csv
    3. store_to_mysql
       - Stores preprocessed data to MySQL table: student_performance
       - Also stores raw data to MySQL table: student_performance_raw
       - Uses SQLAlchemy + pymysql

DAG 02: model_selector_dag.py
  DAG ID: 02_model_selector
  Purpose: Benchmark candidate regression models
  Tasks:
    1. load_data_from_mysql
       - Reads preprocessed data from MySQL
       - Saves to artifacts/preprocessing/data_from_db.csv
    2. evaluate_candidate_models
       - Tests 8 models: LinearRegression, Ridge, Lasso, ElasticNet,
         DecisionTree, RandomForest, GradientBoosting, ExtraTrees
       - Uses 5-fold cross-validation
       - Metrics: RMSE, MAE, R², CV-R² (mean ± std)
       - Saves results to artifacts/model_comparison.json
       - Selects top-3 models based on R² score
    3. summarize_model_selection
       - Prints ranking summary

DAG 03: model_training_dag.py
  DAG ID: 03_model_training
  Purpose: Train top-performing models on full training set
  Tasks:
    1. prepare_train_test_split
       - 80/20 train-test split (random_state=42)
       - Saves X_train, X_test, y_train, y_test as .npy files
       - Saves split_info.json
    2. train_baseline_model
       - Trains LinearRegression as baseline
       - Saves LinearRegression_baseline.joblib
    3. train_best_models
       - Trains top-3 models from model_comparison.json
       - Available registry: LinearRegression, Ridge, RandomForest (200 trees),
         GradientBoosting (200 estimators)
       - Saves each model as {ModelName}_trained.joblib
       - Saves training_results.json

DAG 04: model_tunner_dag.py
  DAG ID: 04_model_tuner
  Purpose: Hyperparameter optimization for RandomForest and GradientBoosting
  Tasks:
    1. tune_random_forest (parallel)
       - RandomizedSearchCV (20 iterations, 5-fold CV)
       - Search space: n_estimators, max_depth, min_samples_split,
         min_samples_leaf, max_features
       - Saves RandomForest_tuned.joblib and tuning JSON
    2. tune_gradient_boosting (parallel)
       - RandomizedSearchCV (20 iterations, 5-fold CV)
       - Search space: n_estimators, learning_rate, max_depth,
         min_samples_split, min_samples_leaf, subsample
       - Saves GradientBoosting_tuned.joblib and tuning JSON
    3. select_best_tuned_model
       - Compares R² of both tuned models
       - Copies the winner as best_tuned_model.joblib
       - Saves best_tuned_model_info.json

DAG 05: model_tester_dag.py
  DAG ID: 05_model_tester
  Purpose: Comprehensive evaluation and sanity testing
  Tasks:
    1. evaluate_trained_models (parallel)
       - Evaluates all *_trained.joblib and *_baseline.joblib models
       - Metrics: RMSE, MAE, R², explained variance, max error, mean error
       - Saves trained_models_metrics.json
    2. evaluate_tuned_models (parallel)
       - Evaluates all *_tuned.joblib models
       - Same metrics as above
       - Saves tuned_models_metrics.json
    3. run_prediction_sanity_checks
       - Picks 10 random samples from test set
       - Checks if absolute error < 20 score points
       - Reports pass rate
       - Saves sanity_checks.json
    4. generate_final_metrics_report
       - Aggregates all metrics
       - Identifies champion model (highest R²)
       - Saves final_metrics_report.json
       - Saves model_metrics.json to artifacts root (consumed by API)

DAG 06: model_extractor_dag.py
  DAG ID: 06_model_extractor
  Purpose: Extract all model files and catalog artifacts
  Tasks:
    1. extract_all_models
       - Copies all .joblib files to artifacts/final_models/
       - Logs extraction in extraction_log.json
    2. identify_champion_model
       - Uses model_metrics.json to find the champion model
       - Copies champion to artifacts/champion_model.joblib
       - Saves champion_model_info.json
    3. generate_artifacts_manifest
       - Catalogs all .joblib and .json files in artifacts/
       - Computes MD5 checksums
       - Saves manifest.json

================================================================================
HOW TO RUN
================================================================================

Prerequisites:
  - Docker and Docker Compose installed
  - At least 4GB RAM available

Start all services:
  docker compose up -d

Initialize (first time only — waits for airflow-init to complete):
  docker compose up airflow-init

Access services:
  - Airflow UI:     http://localhost:8080  (admin / admin)
  - FastAPI Docs:   http://localhost:8000/docs
  - React Frontend: http://localhost:3000
  - MySQL:          localhost:3307

Run the ML pipeline (in order):
  1. In Airflow UI, trigger: 01_dataset_preprocessor_and_csv_to_mysql
  2. After success, trigger: 02_model_selector
  3. After success, trigger: 03_model_training
  4. After success, trigger: 04_model_tuner
  5. After success, trigger: 05_model_tester
  6. After success, trigger: 06_model_extractor

After the pipeline completes:
  - champion_model.joblib will be in artifacts/
  - The API server will load it automatically (or POST /reload-model)
  - The frontend will display predictions and performance metrics

Stop all services:
  docker compose down

Stop and remove volumes (full reset):
  docker compose down -v

PREPROCESSING PIPELINE DETAILS

Input Features (feature_columns in metadata.json):
  [Hours_Studied, Attendance, Sleep_Hours, Previous_Scores,
   Tutoring_Sessions, Physical_Activity,
   Extracurricular_Activities, Internet_Access, Learning_Disabilities,

   Family_Income, Teacher_Quality, Parental_Education_Level,
   Distance_from_Home, Peer_Influence]

Total: 19 features

Preprocessing Steps Applied:
  1. Missing value imputation (median for numeric, mode for categorical)
  2. OrdinalEncoder for 8 ordinal categorical features
  3. LabelEncoder for 5 binary categorical features
  4. StandardScaler for 6 numeric features

Saved Artifacts:
  - numerical_scaler.joblib: StandardScaler fitted on training data
  - ordinal_encoders.joblib: Dict of OrdinalEncoder per ordinal column
  - label_encoders.joblib: Dict of LabelEncoder per binary column
  - metadata.json: Feature names, column types, dataset stats

================================================================================
MODEL DETAILS
================================================================================

Candidate Models (DAG 02):
  - LinearRegression
  - Ridge (alpha=1.0)
  - Lasso (alpha=0.1)
  - ElasticNet (alpha=0.1, l1_ratio=0.5)
  - DecisionTree (max_depth=10)
  - RandomForest (n_estimators=100)
  - GradientBoosting (n_estimators=100)
  - ExtraTrees (n_estimators=100)

Trained Models (DAG 03):
  - LinearRegression (baseline)
  - Top-3 from model selection with more estimators (200 for ensembles)

Tuned Models (DAG 04):
  - RandomForest: 20-iteration RandomizedSearchCV over depth, estimators, splits
  - GradientBoosting: 20-iteration RandomizedSearchCV over lr, depth, subsample

Evaluation Metrics:
  - R² Score: Coefficient of determination (higher = better, max 1.0)
  - RMSE: Root Mean Squared Error (lower = better)
  - MAE: Mean Absolute Error (lower = better)
  - Explained Variance: Fraction of variance explained (higher = better)
  - Max Error: Largest single prediction error
  - Mean Error: Average signed error (bias indicator)

Train/Test Split: 80% train / 20% test (random_state=42)
Cross-validation: 5-fold CV used in selection and tuning phases

NOTES
================================================================================

- The artifacts/ directory is shared between Airflow workers and the API server
  via a Docker volume mount. This enables zero-copy model serving.
- The API server loads the model on startup and provides a /reload-model
  endpoint to refresh without restart after pipeline re-runs.
- The React frontend uses a Vite dev proxy (/api → api-server:8000) in
  development and an Nginx proxy in production.
- DAGs are triggered manually (schedule_interval=None). For production, they
  can be set to a cron schedule or chained using TriggerDagRunOperator.
- All Airflow tasks use PythonOperator for portability. No external connections
  (Airflow Connections) are required — MySQL credentials are passed as
  environment variables.
- The sanity check threshold of 20 score points can be adjusted in
  model_tester_dag.py.
